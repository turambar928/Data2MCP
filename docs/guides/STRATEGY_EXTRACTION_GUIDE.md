# 策略提取机制说明

> 本文档描述系统如何从 PDF 或文本文件中自动识别并抽取结构化分析方法。

---

## 一、整体流程

```
用户上传 PDF / TXT / MD
         │
         ▼
┌─────────────────────┐
│  读取文件内容        │
│  ① 有文字层 → 直接提取文本 (PyMuPDF)
│  ② 无文字层 → 视觉 OCR (gpt-4o)   │
└─────────────────────┘
         │
         ▼
┌─────────────────────┐
│  文本切块            │
│  每块 3000 字符      │
│  相邻块重叠 300 字符 │
└─────────────────────┘
         │
         ▼
┌─────────────────────┐
│  逐块调用 LLM 提取   │
│  返回结构化 JSON     │
└─────────────────────┘
         │
         ▼
┌─────────────────────┐
│  合并去重            │
│  按 key 去重，       │
│  存入 JSON 文件      │
└─────────────────────┘
         │
         ▼
    前端展示，可选用
```

---

## 二、读取 PDF 文字

**代码**：`src/data2mcp_v2/server/strategy_extractor.py`

### 路径 A：数字版 PDF（有文字层）

直接用 **PyMuPDF**（`fitz`）解析 PDF 内置文字层，速度快、质量高，无需调用 AI。

```
PDF 文件 → fitz.open() → page.get_text() → 拼接各页文字
```

### 路径 B：扫描版 PDF（无文字层）

PyMuPDF 读出空字符串时，自动切换 **视觉 OCR** 流程：

```
每页 PDF
  → 渲染为 JPEG 图片（2 倍分辨率）
  → 每 3 页打包，转 base64
  → 发给 gpt-4o（多模态）："请完整转录这几页的全部文字"
  → 收集各批次识别结果，拼成完整文本
```

> 你使用的《情报分析：结构化分析方法》是扫描版，走的是此路径。

---

## 三、文本切块

LLM 上下文有限，无法一次处理整本书，因此将全文分块：

| 参数 | 值 | 说明 |
|------|----|------|
| `chunk_size` | 3000 字符 | 每块大小 |
| `overlap` | 300 字符 | 相邻块重叠区域 |

**重叠的意义**：防止某个方法名称或描述刚好被切断在块边界，重叠区域确保两侧的块都能看到完整内容。

```
全文: ████████████████████████████████████
块1:  ████████████████████
块2:            ████████████████████
块3:                      ████████████████████
       ←──────────────────→
            相邻块各重叠 300 字符
```

## 四、LLM 提取

每个块单独送给 LLM，配合专门的 System Prompt：

**System Prompt 核心指令**（英文，发给模型）：
> 你是识别结构化分析方法的专家。读取文本片段，提取所有独立的分析策略/方法/框架，以 JSON 数组返回，不含其他文字。

**每个方法的数据结构**：

```json
{
  "key":         "analysis_of_competing_hypotheses",
  "name":        "竞争假说分析（ACH）",
  "description": "一句话概括该方法的作用（最多 20 词）",
  "full_text":   "3~6 句给 AI Agent 的具体执行指令，用祈使句写：
                  '列出所有假说。查询数据源收集支持或反驳证据。
                  用矩阵比较各假说与证据的一致性...'",
  "source":      "情报分析：结构化分析方法.pdf"
}
```

> **`full_text` 的设计重点**：不是描述方法"是什么"，而是告诉 Agent"用这个方法时，应该怎样调用数据工具"。这样提取出来的方法可以直接驱动 Agent 执行。

---

## 五、去重与持久化存储

- **去重规则**：多个块可能重复提取同一方法，以 `key` 为唯一标识，相同 key 保留最后一次
- **存储位置**：`config/extracted_strategies.json`
- **合并策略**：新提取结果**追加合并**到已有文件，不同 key 并存，相同 key 覆盖

这意味着你可以上传多本书，每本书的方法会按来源（`source` 字段）区分，在前端按文件名归组展示。

## 六、策略如何驱动 Agent

提取完成后，策略通过以下方式进入 Agent 执行流：

### 用户手动选择

```
用户在界面选择某策略
  → 前端把该策略的 full_text 传给后端
  → Router 将其注入 System Prompt：

      # 🎯 Retrieval Strategy (MUST FOLLOW)
      {full_text}

  → LLM 按策略步骤调用数据工具
```

### 系统自动选择（Auto 模式）

```
用户提问
  → 后端把所有策略的 key + description 列表发给 LLM
  → LLM 根据问题和数据源特征，从列表中选出最合适的策略
  → Router 取出对应 full_text，注入 System Prompt
  → 前端显示本次自动选用的策略名称
```

## 七、涉及的核心文件

| 文件 | 作用 |
|------|------|
| `server/strategy_extractor.py` | PDF 读取、OCR、切块、LLM 提取、存储全流程 |
| `server/strategy_catalog.py` | 加载内置策略 + 合并提取策略，提供统一目录 |
| `server/auto_strategy.py` | 自动策略选择逻辑（LLM 从候选列表中选一个） |
| `server/router.py` | 把策略 full_text 注入 System Prompt，驱动 Agent |
| `server/api.py` | `/api/upload-and-extract` 接口，接收上传文件 |
| `config/extracted_strategies.json` | 所有已提取策略的持久化存储 |
| `demo/src/components/StrategySelector.jsx` | 前端策略管理面板（选择、编辑、删除、上传） |

---

## 八、当前方案的局限

| 问题 | 说明 |
|------|------|
| 遵守率无法保证 | 策略是自然语言，LLM 可能选择性忽略某些步骤 |
| 扫描版 OCR 有损耗 | 图片质量差时，gpt-4o 可能漏字或断句 |
| 提取粒度不稳定 | 同一本书每次提取的方法数量可能略有差异 |
| 无步骤执行追踪 | `full_text` 是整段文字，无法追踪"执行到第几步" |
